# 구글 시트 Gemini 실전 가이드 — 쓰던 시트 그대로 지표·분석·대시보드까지

![Gemini in Sheets](https://img.shields.io/badge/Gemini-in%20Sheets-FF6D5A?style=for-the-badge&logo=googlesheets)

이미 팀이 쓰고 있는 구글 스프레드시트를 **떠나지 않고**, 자연어 지시만으로 파생 지표 열을 만들고 분석하고 보고 화면까지 만들 수 있을까요?

이 가이드는 영상에서 진행한 실습을 그대로 따라할 수 있게 정리한 문서입니다. 영상에서 사용한 **복붙용 프롬프트 원문**, 입력 시트의 **구조와 각 열의 역할**, 그리고 결과를 믿기 전에 **사람이 반드시 확인해야 할 검증 절차**를 담았습니다.

> 📌 **공개 범위 안내.** 이 공개 가이드에는 **영상에서 쓴 전체 실습 데이터 파일(스프레드시트 원본)과 숨김 검산 정답표는 포함하지 않습니다.** 대신 시트의 열 구성과 역할을 설명해 두었으니, 같은 구조로 본인 데이터를 준비하면 동일한 흐름을 재현할 수 있습니다.

> ⚠️ **먼저 알아두세요.** Gemini in Sheets와 Sheets Canvas는 업데이트가 빠른 기능입니다. 메뉴 위치·지원 언어·대상 플랜·롤아웃 상태는 계정과 지역에 따라 다를 수 있습니다. 화면이 이 문서와 다르면 아래 [참고 자료](#10-참고-자료)의 공식 문서를 먼저 확인하세요.

| 이 가이드가 해결하는 것 | 내용 |
|---|---|
| 어떤 문제를 푸나 | 매달 반복되는 시트 지표 계산·분석·보고 화면 만들기 |
| 누구를 위한 가이드인가 | 스프레드시트로 매출·비용·일정을 관리하는 대표·실무자·1인 사업가 |

## 1. 이 가이드가 해결하는 것

4,800행짜리 거래 시트에서 월별 공헌이익을 뽑고, 채널별로 나누고, 미수금을 집계하는 일을 **매달 손으로** 하고 계신다면 이 가이드가 그 반복을 줄여줍니다.

핵심은 도구를 바꾸지 않는다는 점입니다. 새 파일을 만들거나 외부 서비스로 데이터를 옮기지 않고, **지금 열려 있고 팀이 함께 쓰는 그 시트 안에서** 끝냅니다.

| 이럴 때 | 이 가이드 | 이럴 때 | 다른 도구 |
|---|---|---|---|
| 지금 쓰는 시트를 바로 고치고 분석 | Gemini in Sheets | 새 파일을 처음부터 제작 | Claude Code · Codex |
| 팀이 함께 보는 문서에서 즉시 공유 | Gemini in Sheets | 외부 서비스와 자동 연동 | Claude Code · Codex |
| 한 탭 안에서 지표·차트·화면 | Gemini in Sheets | 여러 파일을 묶은 프로젝트 | Claude Code · Codex |

> 💡 둘 중 하나가 낫다는 뜻이 아닙니다. **용도가 다릅니다.**

## 2. 무엇이 달라졌나 — 네 번의 진화

![구글 시트 Gemini, 네 번의 진화](./01-gemini-four-stages.png)

시트의 Gemini는 네 단계를 거쳐 지금에 왔습니다. 예전에는 물어보면 대답만 하는 수준이었지만, 지금은 시트를 직접 고치고 표·피벗·차트·수식을 한 번에 만들며, 읽고 쓰는 화면까지 만듭니다.

| 단계 | 무엇을 하나 | 시점 |
|:---:|---|---|
| ① 답변 | 물어보면 대답 | 초기 |
| ② 편집 | 시트를 직접 고침 | — |
| ③ 전체 작업 | 표·피벗·차트·수식 한 번에 | 2026-04 |
| ④ 앱 (Canvas) | 읽고 쓰는 화면 | 2026-08 |

2026년 6월에는 한국어 지원이 추가되어 ①~③ 단계를 **한국어 지시로** 진행할 수 있습니다.

### 일반 차트와 Canvas는 다릅니다

이 구분을 섞으면 나중에 "왜 안 바뀌지" 하고 헤매게 됩니다.

| 구분 | 일반 편집 가능 차트 | Sheets Canvas |
|---|---|---|
| 형태 | 셀·수식·표 위의 차트 | 시트 위에 올라간 작은 앱 |
| 갱신 기준 | **새로 생성된 차트용 데이터 탭**이 바뀌면 다시 그려짐 | 원본 시트와 **양방향** |
| 원본 탭 수정 시 | 자동으로 따라오지 않음 | Canvas가 따라옴 |
| 화면에서 원본 수정 | 불가 | 가능 |
| 잘 맞는 용도 | 월말 보고, 스냅샷, 인쇄 | 팀 운영 화면, 조건 탐색 |

> ⚠️ 일부 차트 유형은 **이미지로 생성**되기도 합니다. 이미지 차트는 편집도 갱신도 되지 않습니다.

## 4. 실습에 쓴 두 시트의 구조

영상에서는 합성 데이터 두 개를 썼습니다. **파일 자체는 이 공개 가이드에 포함하지 않습니다.** 아래 열 구성을 참고해 본인 데이터를 같은 역할로 맞추면 동일한 프롬프트가 그대로 동작합니다.

### 4-1. 매출·비용 시트

원본 탭 이름은 `원본_매출비용`, **4,800행 × 25열**, 2025-01 ~ 2026-08 (20개월) 거래 데이터입니다.

| 역할 | 열 | 프롬프트에서 쓰이는 곳 |
|---|---|---|
| 식별·시점 | `거래ID` `거래일` `연월` | 월별 집계, 부분 월 판정 |
| 구분 | `거래유형` `카테고리` `항목명` `비용성격` | 매출/비용 분기, 비용 상위 항목 |
| 채널·고객 | `채널` `가상_고객공급사` `신규고객여부` `캠페인` | 채널별 ROAS, 고객 집중도 |
| 조직 | `부서` `담당자` | 보조 분석 |
| 금액 | `수량` `단가` `거래금액` `직접변동원가` `채널수수료` `부가세` | 공헌이익·손익기여액 계산의 핵심 |
| 결제 | `지급기한` `결제상태` `결제금액` `결제일` `결제수단` | 미수금·미지급금·결제지연일 |
| 비고 | `메모` | — |

> 💡 **본인 데이터로 바꾸는 법.** 열 이름이 달라도 됩니다. 프롬프트가 *"수식은 네가 열 이름을 보고 직접 정해줘"* 라고 지시하므로, `거래금액`·`직접변동원가`·`채널수수료`·`결제금액`·`지급기한`에 해당하는 열만 있으면 이름은 자유입니다. 다만 프롬프트 안의 열 이름은 본인 시트에 맞게 바꿔주세요.

### 4-2. 프로젝트 일정 시트

원본 탭 이름은 `원본_프로젝트일정`, **420행 × 20열**, 프로젝트 36개입니다.

| 역할 | 열 |
|---|---|
| 식별 | `업무ID` `프로젝트ID` `프로젝트명` `프로젝트유형` |
| 담당 | `팀` `담당자` |
| 업무 | `업무명` `우선순위` `상태` `진척률` `스프린트` |
| 일정 | `시작일` `마감일` `최근업데이트` |
| 공수 | `예상시간` `실제시간` |
| 리스크 | `블로커여부` `블로커사유` `선행업무ID` |
| 비고 | `메모` |

칸반 프롬프트가 `상태` 값으로 열을 나누므로, **`대기` `진행` `검토` `완료` 네 가지 값**을 쓰는 열이 하나 있어야 합니다.

## 5. 매출·비용 시트 실습 (1~4단계)

### 5-1. 1단계 — 수식을 주지 않고 재무 개념만 설명한다

이 실습의 핵심 접근입니다. 보통은 *"이 열에 이 수식 넣어줘"* 하고 수식을 불러주는데, 그럴 거면 직접 넣는 게 빠릅니다. 받아쓰기만 시킨 셈이니까요.

그래서 **수식을 주지 않고 지표가 사업적으로 무슨 뜻인지만 설명**하고, 어떤 수식을 쓸지는 Gemini가 열 이름을 보고 정하게 둡니다.

```text
원본_매출비용 탭 오른쪽에 아래 일곱 개 열을 새로 만들어줘.
수식은 네가 열 이름을 보고 직접 정해줘. 내가 알려주는 건 각 지표의 의미야.

1) 손익기여액
   - 거래유형이 매출이면: 거래금액에서 직접변동원가와 채널수수료를 뺀 금액
   - 거래유형이 비용이면: 거래금액을 음수로
2) 공헌이익 — 매출 행에만. 거래금액에서 직접변동원가와 채널수수료를 뺀 값.
   비용 행은 공란
3) 공헌이익률 — 공헌이익을 거래금액으로 나눈 값.
   거래금액이 0이거나 비어 있으면 오류 대신 공란
4) 미수금 — 매출 행에서 거래금액에서 결제금액을 뺀 값. 음수면 0
5) 미지급금 — 비용 행에서 거래금액에서 결제금액을 뺀 값. 음수면 0
6) 결제지연일 — 기준일은 2026년 8월 15일.
   미수금이나 미지급금이 남아 있고 지급기한이 기준일보다 이전이면 지난 일수,
   아니면 0
7) 회수위험등급 — 매출 행의 미수금에만 적용해.
   미수금이 없으면 정상, 결제지연일 1~30일 주의,
   31~60일 위험, 61일 이상 심각.
   비용 행과 미지급금은 회수 대상이 아니니까 해당없음으로 표시해줘

조건:
- 원본 4,800행과 기존 25개 열은 수정하거나 삭제하지 마
- 새 열은 기존 열 오른쪽에 추가하고, 4,800행 전체에 채워줘
- 적용하기 전에 각 열에 어떤 수식을 쓸 건지 먼저 설명해줘
```

> 📌 **`손익기여액`은 현금 흐름이 아닙니다.** 아직 안 들어온 돈(미수금)과 안 나간 돈(미지급금)이 섞여 있기 때문입니다. 이 거래가 **영업손익에 얼마나 기여했는지** 보는 값입니다.

> 📌 **`회수위험등급`은 매출 행의 미수금 전용입니다.** 비용 행과 미지급금은 회수 대상이 아니라 `해당없음`으로 둡니다. 미지급금을 회수 위험으로 집계하면 미수금 관리 판단이 틀어집니다. `결제지연일`은 양쪽 모두 계산됩니다 — 우리가 늦게 주는 것도 지연이니까요.

### 5-2. 2단계 — 만들어진 수식을 사람이 검증한다

**만들어졌다고 바로 넘어가면 안 됩니다.** 셀을 눌러 참조를 확인하세요.

| 확인할 것 | 왜 |
|---|---|
| 의도한 열을 참조하는가 | `거래금액` 자리에 `부가세`가 들어가도 숫자는 멀쩡해 보입니다 |
| 마지막 행까지 채워졌는가 | 4,800행이면 헤더 포함 **4,801행**에 값이 있어야 합니다 |
| 총계가 맞는가 | 행 수·총매출·총비용을 별도로 집계해 대조합니다 |

이 대조를 안 하면 "열이 생겼다"는 것만 보고 넘어가게 됩니다.

수식 오류가 났을 때는 2026년 6월에 추가된 기능을 씁니다. 오류 셀 주변 구조를 분석해 원인을 설명하고 수정 수식을 제안합니다.

1. 오류가 표시된 셀을 선택합니다.
2. **Fix 버튼을 눌러 수식 에러 수정을 요청**합니다.
3. 제안된 수식이 올바른 열을 참조하는지 확인한 뒤 적용합니다.

### 5-3. 3단계 — 파생 지표로 분석시킨다

*"분석해줘"* 라고만 하면 거래금액 기준으로 매출이 얼마 늘었다는 얘기가 나옵니다. 이미 아는 숫자죠. 방금 만든 **공헌이익·미수금·결제지연일을 쓰라고 명시**해야 판단 재료가 나옵니다.

```text
방금 만든 파생 열(손익기여액, 공헌이익, 공헌이익률, 미수금,
결제지연일, 회수위험등급)을 반드시 사용해서 분석 탭을 만들어줘.
원본 탭은 그대로 두고.

이 데이터는 2026-08-15 에서 끝나. 2026-08 은 부분 월이야.
8월 반 달을 7월 한 달 전체와 그대로 비교해서 증감률이라고 하지 마.
8월 증감을 보려면 2026-08-01~15 를 2026-07-01~15 와 비교하고,
그게 아니면 8월을 부분 월로 표시하고 월 단위 순위에서 빼줘.

1) 월별로: 매출, 직접변동원가와 채널수수료 합계, 공헌이익과 공헌이익률,
   판관비, 영업이익과 영업이익률, 전월 대비 매출 증감률
2) 채널별로: 매출, 공헌이익, 공헌이익률, 그리고 ROAS.
   ROAS 는 해당 채널 매출을 그 채널에 쓴 광고비로 나눈 값.
   광고비가 0인 채널은 계산하지 말고 해당없음으로 표시해줘
3) 미수금: 총 미수금, 결제지연일 구간별 분포, 회수위험등급별 금액
4) 고객 집중도: 매출 상위 5개 고객과 각각의 비중
5) 손익분기 매출 — 고정비를 공헌이익률로 나눈 값

그리고 위 결과에서 눈에 띄는 변화나 이상 신호를 3~5개 골라줘.
각각에 대해 몇 월인지, 어떤 카테고리·채널인지,
원본의 어느 행이 근거인지 같이 보여줘.

마지막에 경영진이 다음에 확인해야 할 행동을 정리해줘.
확실하지 않은 인과관계는 단정하지 말고 확인이 필요한 가설로 적어줘.
```

### 5-4. 4단계 — 경영 요약 탭 만들기

경영 요약탭에서 **뭘 어디에 놓고, 차트를 몇 개 넣고, 숫자를 어떤 형식으로 보일지까지** 적습니다.
디자인 적으로 더 예쁘게 만들고 싶다면 구체적인 디자인 가이드 문서를 첨부하는 것도 좋은 방법이 될 수 있습니다.

```text
경영 요약이라는 새 탭을 별도로 만들어줘.
원본 탭과 파생 열, 분석 탭은 그대로 두고.

데이터는 2026-08-15 에서 끝나니까 8월 값은 전부 누계로 표시해줘.

맨 위에 핵심 지표를 카드 형태로 나란히 놓아줘.
- 2026-08-15 누계 매출
- 2026-08-15 누계 영업이익
- 2026-08-15 누계 영업이익률
- 미수금 잔액 (2026-08-15 기준)
- 최근 90일 채널 ROAS 최고·최저

그 아래에 경영진이 알아야 할 것 세 줄. 한 줄에 한 문장으로.
8월 누계 수치와 7월까지 완결된 달의 추세를 반드시 구분해서 써줘.

그 아래에 편집 가능한 차트 세 개:
1) 월별 매출과 영업이익 — 매출은 막대, 영업이익은 선
2) 채널별 매출과 공헌이익률 비교
3) 비용 구조와 회수위험등급별 미수금.
   이 두 가지를 가장 잘 보여주는 차트 유형은 네가 골라줘

그 아래에 표 세 개:
- 비용 상위 항목
- 매출 상위 5개 고객과 비중
- 손익분기 매출과 현재 매출 대비 여유

형식은 이렇게 해줘.
- 각 차트와 표에 제목을 넣어줘
- 금액은 천 단위 구분, 비율은 퍼센트로
- 색은 매출 계열·비용 계열·위험 계열 세 가지로만 통일하고
  장식용 요소는 넣지 마
```

만든 뒤 확인할 것:

| 확인 | 기준 |
|---|---|
| KPI 카드 | 요청한 5개가 모두 생성됐는가 |
| 누계 라벨 | 부분 월 값에 `누계` 표기가 붙었는가 |
| 차트 | 3개가 모두 생성됐고 **편집 가능한** 형태인가 (이미지가 아닌가) |
| 차트용 데이터 탭 | 차트와 함께 새 탭이 생겼는가 |
| 숫자 | 카드 값이 시트 합계와 일치하는가 |

## 6. Canvas 실습 — 재무 대시보드와 프로젝트 칸반

Canvas는 계정 언어를 영어로 바꿔야 진입점이 나타납니다. 스프레드시트 하단의 Canvas 아이콘을 누르면 Gemini 사이드 패널이 열리면서 Canvas 도구가 선택됩니다.

공식 안내는 *"대시보드 만들어줘"* 처럼 막연하게 쓰지 말고 **무엇을 보려는지, 필터가 필요한지까지** 적으라고 권합니다.

### 6-1. 재무 대시보드

경영 요약 탭에 넣었던 것과 **같은 지표**로 요청합니다. 조건이 같아야 두 결과를 비교할 수 있습니다.

```text
Build a finance dashboard from this sheet.

Show monthly revenue, direct variable cost and channel fee,
contribution profit and contribution margin rate,
operating profit and operating margin,
outstanding accounts receivable, and ROAS by channel.

Add filters for month and channel.

Let me explore which cost items drive the change,
and which receivables are at collection risk.

Display labels in Korean if supported.
```

Canvas는 스프레드시트 안에 **새 탭으로** 나타납니다. 별도 파일이나 사이트가 아닙니다.

> 💡 마지막 줄에서 한국어 표시를 요청하지만, 지원 여부는 계정·롤아웃 상태에 따라 다를 수 있습니다. 안 되면 영어 라벨로 나옵니다.

### 6-2. 프로젝트 칸반

두 번째 시트로 **양방향이 실제로 동작하는지**만 확인합니다.

```text
Create a Kanban board from this sheet.

Group the cards into four status columns using these Korean status values:
- 대기
- 진행
- 검토
- 완료

Each card should display the following fields. Keep the field labels in Korean:
- 프로젝트명
- 업무명
- 담당자
- 마감일
- 우선순위
- 블로커여부

Add filters for the following fields, also using the Korean field labels:
- 프로젝트명
- 담당자
- 팀
- 우선순위

Use clear color cues to highlight:
- Items with 우선순위 = 긴급
- Tasks that are past their 마감일
- Tasks where 블로커여부 indicates that the task is blocked

Allow users to:
- Move cards between status columns
- Add new tasks
- Edit the 메모 field

Important: Use English for all implementation instructions and internal logic, but keep all user-facing field names, status values, priority values, and existing sheet data in Korean.
```

> 💡 **왜 지시문은 영어이고 필드명은 한국어인가.** 프롬프트 마지막 줄이 그렇게 지시합니다. Canvas가 영어 계정에서 동작하므로 구현 지시는 영어로 주되, 시트의 기존 데이터와 사용자에게 보이는 라벨은 한국어를 유지시키는 방식입니다.

만든 뒤 양방향을 확인합니다.

1. 카드 하나를 `진행` → `검토`로 옮기고 원본 탭에서 해당 행의 `상태`가 바뀌었는지 확인
2. 칸반에서 새 작업을 추가하고 원본에 행이 생겼는지 확인
3. 카드의 `메모`를 고치고 원본에 반영됐는지 확인
4. 반대로 **원본에서** `상태` 값을 바꾸고 칸반으로 돌아가 카드가 옮겨졌는지 확인

> 📌 공유는 **스프레드시트에 이미 있는 권한을 그대로** 씁니다. Canvas 전용 권한 체계가 따로 생기지 않습니다.

### 검증 체크리스트

결과를 믿기 전에 아래를 사람이 직접 확인하세요. 이 표가 이 가이드에서 가장 중요한 부분입니다.

| # | 확인 항목 | 통과 기준 | 실패하면 |
|:--:|---|---|---|
| 1 | 파생 열 채우기 범위 | 헤더 포함 마지막 행까지 값이 있음 | 범위가 끊긴 화면을 확인하고 지시문에 행 수를 명시 |
| 2 | 수식 참조 열 | 의도한 열을 참조 | 셀을 눌러 참조 범위를 직접 교정 |
| 3 | 원본 보존 | 원본 행 수·금액이 실습 전과 동일 | 되돌리고 "삭제·수정 금지"를 지시문에 추가 |
| 4 | 총계 대조 | 별도 집계한 총매출·총비용과 일치 | 어떤 지표가 어긋났는지 셀 단위로 추적 |
| 5 | 부분 월 처리 | 마지막 달이 누계로 표기되거나 순위에서 제외 | 부분 월 문구를 프롬프트에 다시 넣고 재실행 |
| 6 | 회수위험 범위 | 비용 행·미지급금이 `해당없음` | 등급 정의를 채권 전용으로 다시 지시 |
| 7 | ROAS 계산 | 광고비 0인 채널이 `해당없음` | 0 나눗셈 처리를 지시문에 명시 |
| 8 | 차트 편집 가능 여부 | 이미지가 아닌 편집 가능한 차트 | 이미지로 나왔다면 차트 유형을 바꿔 재요청 |
| 9 | Canvas 양방향 | 4가지 동작이 원본에 반영 | 반영 안 되는 항목을 구분해 기록 |
| 10 | 분석의 인과 주장 | 단정 대신 확인이 필요한 가설로 서술 | 근거 행으로 직접 이동해 대조 |

> ⚠️ **이 공개 가이드에는 검산 정답표가 포함되지 않습니다.** 영상에서는 미리 계산해둔 값과 대조했지만, 그 정답 수치는 공개 패키지에 넣지 않습니다. 본인 데이터로 실습할 때는 **피벗 테이블이나 별도 `SUM` 집계로 직접 정답을 만들어** 대조하세요. 그게 이 검증 절차의 핵심입니다.

## 8. 한계와 주의사항

| 한계 | 내용 | 대응 |
|---|---|---|
| Canvas 언어 | 계정 언어가 영어일 때만 공식 지원 | 앞 단계는 한국어로, Canvas만 언어 전환 |
| Canvas 플랫폼 | 웹 전용 | 모바일 앱에서는 진입점 없음 |
| Canvas 롤아웃 | 순차 배포 중 | 조건을 맞춰도 계정에 따라 미노출 가능 |
| Canvas 사용량 | 사용자별 사용량 제한 | 반복 생성 시 제한에 걸릴 수 있음 |
| Canvas 데이터 범위 | 한 개 탭만 사용 | 여러 탭에 흩어진 데이터는 먼저 한 탭으로 모아야 함 |
| Canvas 미노출 조건 | 모바일, 너무 큰 탭, 다운로드·복사·인쇄 제한, 외부 저장소·오프라인 상태에서는 안 보일 수 있음 | 웹·탭 크기·파일 권한·저장 위치·온라인 상태를 차례로 확인 |
| 차트 갱신 | 차트용 데이터 탭 기준. 원본 탭 변경에는 무반응 | 원본과 연동이 필요하면 Canvas 사용 |
| 이미지 차트 | 일부 유형은 편집·갱신 불가 | 편집 가능한 차트로 재요청 |
| 시트 규모 | 탭이 많거나 열이 훨씬 많으면 지시를 잘게 쪼개야 함 | 단계별로 나눠 요청 |

> ⚠️ **가장 흔한 함정 세 가지** — ① 파생 열이 중간에서 끊긴 걸 모르고 합계를 믿는 것, ② 부분 월을 완결 월과 비교해 없는 급감을 보고하는 것, ③ 일반 차트가 원본과 실시간 연동된다고 착각하는 것.

## 9. FAQ

**Q. 시트에 Gemini 아이콘이 안 보입니다.**
워크스페이스 스마트 기능이 켜져 있는지, 그리고 계정이 대상 플랜인지 확인하세요. 비즈니스 스탠다드·플러스, 엔터프라이즈 스탠다드·플러스, 구글 AI 프로·울트라가 대상입니다. 자세한 대상자는 아래 링크를 참고해주세요.
https://support.google.com/docs/answer/17035851?hl=ko

**Q. Canvas 아이콘이 안 보입니다.**
Canvas는 **웹에서 계정 언어가 영어일 때** 공식 지원됩니다. 모바일, 너무 큰 탭, 다운로드·복사·인쇄가 제한된 파일, 외부 저장소 또는 오프라인 상태에서도 안 보일 수 있습니다. 이 조건과 스마트 기능·대상 플랜을 모두 확인했는데도 보이지 않는다면 순차 배포가 아직 도달하지 않았을 가능성이 남습니다.

**Q. 프롬프트에 있는 열 이름이 제 시트와 다릅니다.**
프롬프트 안의 열 이름을 본인 시트 이름으로 바꾸면 됩니다. 수식 자체는 지정하지 않으므로, 각 지표의 **의미 설명**만 유지하면 동작합니다.

**Q. 원본 데이터가 지워지거나 바뀌지 않을까요?**
프롬프트에 *"원본 4,800행과 기존 25개 열은 수정하거나 삭제하지 마"* 라는 조건이 들어 있습니다. 다만 지시가 항상 지켜진다고 가정하지 말고, 실습 전 사본을 만들고 실습 후 행 수와 총계를 대조하세요.

**Q. 만든 차트가 원본을 고쳐도 안 바뀝니다.**
정상 동작입니다. 편집 가능한 차트는 **새로 생성된 차트용 데이터 탭**을 기준으로 갱신됩니다. 원본 시트와 양방향으로 연결되는 것은 Canvas입니다.

**Q. 마지막 달 매출이 갑자기 반토막으로 나옵니다.**
데이터가 그 달 중간에서 끝나는 **부분 월**일 가능성이 높습니다. 3단계 프롬프트의 부분 월 안내 문구를 본인 데이터의 마지막 날짜로 바꿔 넣으세요.

**Q. 영상에서 쓴 실습 파일을 받을 수 있나요?**
공개 가이드에는 전체 데이터 파일과 검산 정답표를 포함하지 않습니다. 위 [4장](#4-실습에-쓴-두-시트의-구조)의 열 구성을 참고해 본인 데이터로 준비하시면 같은 프롬프트가 그대로 동작합니다.
